## 发布简介（`outputs/第N期/发布简介.md`）

模板在 `templates/发布简介.md`。第 4 期的写法：

- **标题**：一个问句点出要重估的默认答案 + `｜重估 第 N 期`，例如「学历，到底还值多少？｜重估 第 4 期」。
- **简介**：两段，一人一段。先讲一个具体经历（顾东政的第一份实习、原同翻两年的 AI 聊天记录），再落到他自己的结论，尽量用原话。
- **免责**：聊到资本市场、投资时加「只是一种外部评价的方式，不聊买卖和收益，不构成投资建议」。
- **章节时间**：每章第一句在成片上的时间（`build_ep.py` 的时间线 + 片头长度）。
- **话题**：`#重估播客 #主题 #大学 #AI #个人成长 #播客` 这一类。
- **图片来源**：照片和新闻截图逐条列出（名称：作者，许可，链接）。

拆成两期时各写一份（`发布简介_N.1.md`、`_N.2.md`），再各写一份小红书版（`小红书_N.1.md`）：标题不超过 20 字、给一个备选标题，正文口语化、可以带少量 emoji，结尾放章节。

## 平台规矩

- 抖音会把外链当导流：简介里不放链接。
- 话题避开：财富自由、理财、投资、留学、股市、变现、副业、赚钱、算卦；不要单独的 `#重估`（股票圈的「价值重估」会被归到财经）。
- 可能被误伤的句子在剪辑时删掉（第 4 期删了政治身份标签、「淹死的人」、「算卦」、粗口评价排名等），每一条都写进该期 README 的「剪掉的内容」。
- 字幕里「牛逼」写「牛X」，画面上不出现。

第 4 期用的上传脚本是 `work/upload4.sh`：浅克隆 + sparse checkout，只检出要改的文件；`output` 分支里 `第N期/` 已存在时拒绝覆盖（要更新就改成更新模式）。提交作者是 `Wu YuanTong <231900814+YuanTong-Wu@users.noreply.github.com>`。

仓库里 `CLAUDE.md`（`main-lnfk8p` 分支）定的发布规矩，每期都照做：

1. 成片放进 `第N期/`；同一期更新用 `_v2`、`_v3` 后缀，旧版本留在分支历史里。
2. 按 42 MiB 拆成 `*.part_aa`……并附 `.sha256`；该期 README 写版本说明和 Mac 上拼回的命令。
3. 更新 `output` 根目录 README 的索引表。
4. 推完从远端重新 clone 一份拼回，核对 sha256。
5. 另转一个 30 MB 以内的 720p 预览版直接发给用户（`ffmpeg -i 成片 -vf scale=-2:960 -c:v libx264 -crf 28 -c:a aac -b:a 96k 预览.mp4`，竖版就按高度缩）。

用户回复偏短，喜欢直接出结果，回复用中文。`chonggu.sh pack` 只在本地准备好 `outputs/第N期/`；push 要用户点头后再做。

这台 Mac 上推送前先 `gh auth status`；没登录就 `gh auth login --web`（让用户在浏览器里输验证码）再 `gh auth setup-git`。
